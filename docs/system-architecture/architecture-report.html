Function and endpoint search

Frontend — Runtime: Browser

108 Jinja templates; CSS: dashboard, role themes, login, borrowers, motion; JS: dashboard, motion, document preview. Initial pages are server rendered. Native forms dominate; fetch/XHR enhances previews, drafts, OTP, badges, checklist and administration.

Backend — Runtime: Python serverless

backend/app/main.py exports app = FastAPI(). Auth/users/mobile routers use /api/v1 prefixes; the browser loan router is unprefixed. Pydantic, Form, Query, Path and UploadFile validate inputs.

Authentication and authorization

JWT bearer or HttpOnly session cookie → get_current_user → cached/user repository lookup → RoleChecker. Client intake uses a separate signed client-session dependency.

Data and external services

PostgreSQL through an async SQLAlchemy adapter; SQLite locally. Redis supports rate limiting/cache. Cloudinary stores authenticated production files. QoreID, CreditRegistry, CRC, Youverify and an Emailope-compatible endpoint are runtime integrations.

Vercel deployment — Runtime: Build/Deployment

pyproject.toml selects backend.app.main:app; root requirements.txt and Python 3.12.11 configure the build. No vercel.json or independent frontend build exists. Actual dashboard configuration is unverified.
